# Only callers admitted by the resolved account configuration may create Part information

Ordinary Part creation requires parts.create. Imported creation requires parts.import and does not acquire ordinary-create parity. Provider-assisted Web creation checks info_providers.create_parts without additionally checking parts.create. Actor-supplied Favorite in the Web creation form requires parts.change_favorite together with that form’s actual enclosing creation guard; a default false value is not an Actor-authorized input. Import and MCP fields do not silently inherit this Web control restriction. Supported dependent creation in an enclosing new Part follows that creation path’s guard; existing-parent MCP nesting uses edit rather than independent ordinary-create authority.

## Rationale

Authority is supplied by the resolved User’s stored Permission overrides and the consulted Group chain. Explicit User values win; unresolved inheritance is denied. An authenticated token already carrying a disabled User is refused before permission lookup. Anonymous Web requests resolve the reserved anonymous User identity. PAT and OAuth role/scope ceilings are applied before inherited permission resolution and cannot enlarge User authority. REST and KiCad require authenticated api.access_api; MCP requires authenticated api.use_mcp and endpoint enablement, with editing enablement on the explicit write processors. The initiating API client, AI agent or KiCad client remains the caller; its authenticated User supplies authority rather than a fictitious stored caller registry.
